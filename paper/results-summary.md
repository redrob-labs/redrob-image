# 실험 정리 (논문 집필용, 2026-10-26 기준)

Z-Image로 한국어 글자를 정확히 그리게 하는 실험의 결과 모음. 숫자는 모두 `paper/runs/` 아래 결과 파일에서 옮김.
에이전트가 정리한 초안이며, 본문은 저자가 직접 다시 써야 함(`paper/ai-usage.md` 참고).

## 1. 문제와 평가

- 목표: 프롬프트에 적힌 한국어 문구를 획까지 정확히 그림. 특히 학습에 없던 단어(unseen)와 음절.
- 평가 세트: 프롬프트 220개 (seen 단어 100, unseen 단어 100, unseen 음절 20). 길이 묶음 1~2 / 3~5 / 6~10 / 11+ 음절. 1024px, 28 step, cfg 4.0.
- 중간 평가: 같은 세트의 40개, 시드 1개. 표본이 작아 흔들림이 큼(5절).
- 지표: CER, 정확히 맞춤(EM).
- **채점 규칙(dual OCR)**: PaddleOCR(korean PP-OCRv5)과 qwen3vl-8b가 둘 다 맞게 읽어야 맞음. CER은 둘 중 나쁜 값.
  - 이유: qwen3vl 단독 채점은 장면을 보고 단어를 짐작함. 글자가 아닌 그림을 "약국"으로 읽은 사례가 있음.
  - 효과: qwen 단독 대비 EM이 8~9%p 낮아짐. 모델 순서는 바뀌지 않음.
  - 근거: `paper/runs/dual-ocr-rescore.md`, `scripts/rescore_dual.py`

## 3. 실험 1: LoRA 미세조정

| 설정 | r32 | r64 v2 |
|---|---|---|
| LoRA 위치·rank | attention, 32 | attention + FFN, 64 |
| loss | 이미지 전체 평균 | 글자 상자 안 5배 가중 |
| timestep | 스케줄러 격자 | logit-normal |
| 16px 미만 글자 | 512에서도 학습 | 1024 단계에서만 |
| 단계 | 512px 2 epoch + 1024px 1,500 step (11,500) | 512px + 1024px 3,000 step (12,216) |

- 박스: L40S 48GB 1장. r32 초당 1.7장, r64 v2 초당 1.1장, 최대 메모리 24.8GB.

**최종 결과 (220개, dual OCR)**

| 모델 | CER | seen CER | unseen CER | EM | seen EM | unseen EM |
|---|---:|---:|---:|---:|---:|---:|
| Base | 0.410 | 0.313 | 0.423 | 0.18 | 0.25 | 0.14 |
| Base + r32 | 0.355 | 0.263 | 0.356 | 0.21 | 0.28 | 0.18 |
| **Base + r64 v2** | **0.281** | **0.151** | **0.312** | **0.30** | **0.48** | **0.19** |
| Turbo | 0.519 | 0.477 | 0.491 | 0.07 | 0.10 | 0.06 |
| Turbo + r32 | 0.467 | 0.429 | 0.423 | 0.09 | 0.10 | 0.10 |
| Turbo + r64 v2 | 0.457 | 0.381 | 0.456 | 0.12 | 0.18 | 0.08 |

발견:

1. seen 단어는 크게 좋아짐(EM 0.25 -> 0.48). unseen 단어 EM은 0.14 -> 0.19로 거의 그대로.
2. 긴 문구가 가장 좋아짐. Base는 문구를 중간에 끊음("도깨비방망이가게" -> "도깨비"). LoRA는 글자 수·배치를 맞춤.
3. 남는 오류는 모음·쌍자음 한 획(깨->꺼, 게->계, 책->착). 같은 오류가 step 2500부터 끝까지 그대로.
4. Base에서 학습한 LoRA는 Turbo에 잘 안 옮겨감.
5. 검증 loss는 글자 품질을 거의 반영하지 않음. r32에서 loss −2%일 때 CER −13%.
6. r64 v2는 네 가지를 한꺼번에 바꿔 요인별 효과를 나눌 수 없음(ablation 없음).

해석(가설, 검증 안 함): VAE 8배 축소 + 2x2 패치로 토큰 하나가 16x16px. 모음 획은 그보다 작음. 텍스트 인코더도 음절·바이트 토큰이라 자모 구조를 직접 보지 못함.

근거: `paper/runs/pilot-r32/final/`, `paper/runs/pilot-r64v2/final/`, `paper/runs/compare-step10000/`

## 4. 실험 2: 글리프 조건 (부정적 결과)

목표 글자를 폰트로 그린 이미지(글리프)를 조건으로 넣음. 검증법은 **바꿔치기 시험**: 프롬프트 글자 A, 글리프 글자 B를 주고 무엇을 그리는지 봄(10장).

| 방식 | 캡션에 글자 있음 | 캡션 글자 가림 | 학습 속도 |
|---|---|---|---|
| 학습 전 (글리프만, LoRA 없음) | 10장 중 dual 맞춤 0 | | |
| omni 모드 조건 + LoRA (v1, step 3141·5000) | A·B 섞임, B 복사 0/10 | 안 함 | 초당 0.62장 |
| 채널 붙이기 ch1 (step 5245) | 10/10 A | 안 함 | 초당 1.17장 |
| 채널 붙이기 ch2, 캡션 60% `*` 가림 (step 2650·3001) | 10/10 A | 0/10 B, 잡글자 (dual CER 0.98) | 초당 1.16장 |

발견:

1. omni 모드는 글리프를 "힌트"로만 씀. step이 늘어도 B를 따르는 비율이 줄어듦.
2. 채널 붙이기는 투영층이 학습돼도(가중치 노름 0 -> 2.31) 글리프를 무시함. 학습 중 캡션과 글리프가 늘 같아서 글리프가 필요 없는 입력이 됨.
3. 캡션을 가려도 글리프를 베끼지 못하고 잡글자를 그림.
4. 결론: LoRA 규모의 학습으로는 이 모델에 글리프 복사 능력을 넣지 못함. ControlNet 같은 별도 분기가 필요할 것으로 봄(시험 안 함).

근거: `paper/runs/glyph-swap-step3141/`, `glyph-swap-step5000/`, `glyph-ch2-swap-step2650/`, `glyph-ch2-swap-masked-step3001/`

## 5. 실험 3: 폰트로 얹고 다듬기 (부정적 결과)

모델이 빈 장면을 그리고, 글자는 폰트로 얹은 뒤 둘레나 전체를 다시 그림. 20개, 글자 상자만 잘라 dual 채점.

| 방식 | EM | seen EM | unseen EM |
|---|---:|---:|---:|
| 폰트만 얹음 | 0.30 | 0.50 | 0.17 |
| 둘레 inpaint b16 s0.3 | 0.35 | | |
| 글자째 다시 그림 (r64 v2) s0.35 | 0.40 | 0.62 | 0.25 |
| 같음 s0.5 | 0.25 | 0.62 | 0.00 |
| 같음 s0.65 | 0.10 | 0.25 | 0.00 |
| Qwen-Image-Edit-2511 | 0.20 | 0.12 | 0.25 |

발견:

1. 다시 그리는 세기를 올리면 글자가 망가짐. 약하면 붙여 넣은 티가 남음. 저자 판정: 모든 설정이 티가 남.
2. 편집 모델은 글자를 바꿔 버림(커피 -> 머머, 주차장 -> 수라장).
3. 깨끗한 폰트 글자도 OCR EM이 0.30뿐. 기존 OCR은 처음 보는 음절(뇱, 꾔, 툟)을 못 읽음. 그래서 OCR 점수는 이 방식의 품질을 재지 못함.

근거: `paper/runs/render-harmonize-trial/`, `paper/runs/rerender-trial/`

## 6. 실험 4: 보상 모델 (진행 중)

보상 학습 전에 보상이 자모 하나 차이를 가려내는지 검사(0단계).

- 시험 세트: 프롬프트 100개, 정답 하나당 자모 하나만 바꾼 오답 쌍 498개(모음 173, 쌍자음 96, 초성 99, 받침 130, 처음 보는 음절 85). 같은 장면, 같은 폰트.
- 통과 기준: 정답을 더 높게 매기는 비율 95% 이상.

| 보상 | 맞힘 | 모음 | 쌍자음 | 초성 | 받침 | 처음 보는 음절 |
|---|---:|---:|---:|---:|---:|---:|
| v1 VLM 판정 + dual OCR + 헛글자 | 0.785 | 0.665 | 0.812 | 0.889 | 0.846 | 0.588 |
| v2 Qwen3-VL 글자 상자 우도 | 0.829 | 0.740 | 0.854 | 0.919 | 0.862 | 0.635 |
| v5 음절 칸별 우도 + 상자 우도 | 0.894 | 0.809 | 0.927 | 0.970 | 0.923 | 0.859 |
| v6 음절 분류기 (깨끗한 배경) | 0.954 | 0.954 | 0.958 | 0.939 | 0.962 | 1.000 |
| **v7 음절 분류기 (+ 사진 배경·테두리)** | **0.998** | 1.000 | 1.000 | 0.990 | 1.000 | 1.000 |

- 분류기: ResNet-18, 11,172음절 전부, OFL 폰트 34개로 학습. 시험 세트 폰트(Noto Sans KR)는 학습에서 뺌. 점수 = 칸별 log P(목표 음절) 평균, 실행 전에 정함.
- 정답 이미지를 정확히 읽은 비율: v6 0.39, v7 0.89.
- 한계 1: v5 가중치는 같은 498쌍으로 고름(낙관적). v7 변경은 100개 중 40개를 보고 정함. 나머지 60개(298쌍)에서 맞힘 1.000, 정확히 읽음 0.83.
- 한계 2: 시험 세트는 폰트 합성. 모델이 그린 그림에서는 사람 판정과 비교해야 함(r64 v2 20장, 저자 판정 대기).
- 발견: 범용 VLM은 드문·처음 보는 음절을 정답이어도 못 읽음(정답 음절 log-prob < −5가 실패의 절반). 음절 단위 분류기가 이 문제를 풂.

근거: `paper/runs/reward-check/`, `scripts/reward.py`, `scripts/syllable_cls.py`, `scripts/reward_cls.py`

**1단계 롤아웃 (진행 중)**

- 학습용 프롬프트 2,000개(평가 세트와 겹치지 않음), 프롬프트당 Base + r64 v2로 4장.
- 시험분 200개(800장): dual EM 0.31. 200개 중 194개 묶음에서 4장 사이 보상 차이 > 0.1 -> 좋은·나쁜 쌍을 만들 수 있음.
- 전체 2,000개 생성 중. 다음은 글자 상자 안 DPO 학습.

## 7. 논문에 쓸 때 주의

1. 중간 평가 40개·시드 1개 결과는 흔들림이 큼. r32 step 5000에서 unseen이 나빠 보였다가 220개로 다시 재니 좋아짐. 결론은 220개 결과로만.
2. 1~2음절 CER은 채점 함정이 있음. OCR이 읽은 여러 줄 중 가장 잘 맞는 줄로 재서, 헛글자를 많이 그린 Base가 유리함.
3. PaddleOCR 단독으로만 잰 결과(`full-eval-*`, `quick-paddle/*`)는 dual로 다시 안 잼. 섞어 쓰지 말 것.
4. r64 v2의 개선은 네 변경의 합. 요인별 주장은 못 함.
5. 실험 2·3은 부정적 결과로 보고 가치가 있음(바꿔치기 시험은 조건 사용 여부를 재는 간단한 방법).
