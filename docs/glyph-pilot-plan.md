# 글자 모양 조건(glyph) 파일럿 계획

## 왜

LoRA 파일럿(r32, r64 v2)은 글자 배치와 길이는 맞추지만 모음·쌍자음 획을 못 그린다.
step 10000 기준 CER 0.24, 정확히 맞춤 27%. 텍스트 인코더가 음절 토큰만 넘겨서
모델이 획 모양을 직접 보지 못하기 때문이다. 목표 글자를 폰트로 그린 이미지를
조건으로 같이 넣어, 모델이 획을 "보고 옮겨 그리게" 한다(EasyText, AnyText 계열).

## 방식: Z-Image omni 모드에 글리프 이미지 1장 추가

diffusers `ZImageTransformer2DModel`에는 이미 omni 모드가 있다.

- `x`를 이미지 목록의 목록으로 넘기면 조건 이미지와 목표 이미지를 한 시퀀스에 넣는다.
- 조건 이미지는 `noise_mask=0`으로 들어가고, t=1(깨끗함) 임베딩으로 변조된다.
- 조건 이미지마다 위치 id의 첫 축(frame)만 다르고, 세로·가로 축은 0부터 같다.
  그래서 글리프 토큰과 목표 이미지 토큰이 같은 자리끼리 맞물린다.

새 파라미터가 없다. 기존 LoRA(attention + FFN)만 학습한다.

입력 순서: `[글리프 이미지(clean), 목표 이미지(noisy)]`, noise_mask `[0, 1]`.
loss는 목표 이미지 토큰에서만 계산한다.

## 글리프 이미지 만들기

| 항목 | 값 |
|---|---|
| 크기 | 목표 이미지와 같음(512 또는 1024) |
| 배경 / 글자 | 검정 / 흰색 |
| 폰트 | Noto Sans KR 한 가지로 고정(OFL, 한글 11,172자 전부) |
| 위치 | 라벨 상자(사각형·사각 polygon)에 원근 변환으로 맞춤 |
| 라벨 없는 글자 | 그리지 않음(이미 그런 crop은 파서가 뺌) |
| 인코딩 | 같은 VAE로 latent를 만들어 사전 계산에 저장 |

폰트를 고정하는 이유: 글리프는 "어떤 획인가"만 알려 주고, 서체·색·질감은 캡션과
장면에서 배우게 한다. 고정 폰트가 Noto라 unseen 음절도 글리프로는 전부 들어간다.

## 학습 설정(r64 v2에서 바뀌는 것만)

| 항목 | r64 v2 | glyph v1 |
|---|---|---|
| 조건 | 텍스트만 | 텍스트 + 글리프 이미지 |
| 글리프 dropout | - | 15%(글리프 없이도 그리게) |
| 나머지 | LoRA r64 attn+FFN, 글자 영역 5배, logit-normal, 1024 3000스텝 | 같음 |

512px에서 시퀀스가 이미지 토큰 1024개 + 글리프 1024개로 늘어 스텝이 느려진다.
속도는 스모크에서 다시 잰다.

## 평가

- 프롬프트 220개는 그대로. 프롬프트마다 글자 상자 1개를 메타데이터에 추가한다
  (장면별 고정 배치: 간판 가운데 위, 포스터 위쪽, 메뉴판 왼쪽 열 등).
- 채점: qwen3vl CER·정확히 맞춤 + PaddleOCR 빠른 점수.
- unseen 음절 20개는 OCR이 못 읽으므로 사람이 직접 본다.
- 비교 기준: Base, r32, r64 v2 최종.

통과 기준(파일럿):

| 지표 | 기준 |
|---|---|
| unseen 단어 CER | 0.10 이하 |
| 정확히 맞춤(전체) | 0.60 이상 |
| unseen 음절 사람 판정 | 20개 중 15개 이상 맞음 |
| 글리프 없이(dropout) 생성 | r64 v2보다 나빠지지 않음 |

## 순서

1. `scripts/render_glyph.py`: 라벨 → 글리프 이미지. 샘플 20개를 원본 위에 겹쳐 위치 확인.
2. `precompute.py`에 글리프 latent 추가 → `~/data/precomp-glyph`(512 전부, 1024 소스당 6000).
3. 학습기: omni 입력, 글리프 dropout, 목표 토큰만 loss. 설정 `configs/g6e-glyph-v1.yaml`.
4. 평가 스크립트에 `--glyph` 와 상자 메타데이터 추가.
5. 스모크 100스텝 → 파일럿 전체 → 최종 평가.

GPU는 r64 v2가 끝난 뒤에 쓴다. 1~4번 코드는 그동안 쓴다.

## 위험

| 위험 | 확인 방법 |
|---|---|
| 글자가 장면에 안 녹고 붙여 넣은 듯 보임 | 샘플 사람 판정, 실사 검증 loss |
| 서체가 늘 Noto처럼 나옴 | 캡션에 서체를 바꾼 프롬프트 묶음으로 비교 |
| 사용할 때 상자를 정해야 함 | 제품 단계에서 장면별 기본 배치 또는 LLM 배치로 해결(파일럿 범위 밖) |
| omni 모드가 Base 가중치에서 학습된 적 없을 수 있음 | 스모크에서 글리프만 넣고 LoRA 없이 생성해 반응을 먼저 본다 |
