# C안: 보상 학습으로 글자 획을 고친다 (preference / RL post-training)

## 왜

| 해 본 것 | 결과 |
|---|---|
| LoRA r32 / r64 v2 (지도학습) | unseen 단어 dual 맞춤 18% / 19%. 모음 획이 틀린 채 굳음 |
| 글리프 조건 3종 (omni, ch1, ch2) | 바꿔치기 시험 0/10. 글리프를 베끼지 않음 |
| B안 render -> harmonize | 글자는 정확, 그러나 전부 "붙여 넣은 티" (사람 판정) |

지도학습 loss는 이미지 전체 평균이라 획 하나가 틀려도 거의 안 늘어난다(검증 loss 2% vs CER 13%).
보상 학습은 "글자가 맞았나"를 직접 신호로 쓴다.

## 근거

- TextAlign ([arXiv 2605.19320](https://arxiv.org/abs/2605.19320)): 구조는 그대로 두고, VLM 보상을 전체·단어·글리프 세 층의 결함 판정으로
  나눠 GRPO/DPO에 씀. Z-Image-Turbo와 FLUX.1-dev에서 OCR 정확도가 오르고 일반 품질은 유지.
- GlyphPrinter ([arXiv 2603.15616](https://arxiv.org/abs/2603.15616), CVPR 2026): OCR 보상은 세밀한 획 오류에 둔하다(우리도 확인: qwen3vl이
  획 없는 간판을 "약국"으로 읽음). 그래서 글자 영역 단위 선호쌍으로 DPO(R-GDPO).
- CRD ([arXiv 2603.14128](https://arxiv.org/abs/2603.14128)): OCR 보상 RL. 보상 해킹은 학습에 안 쓴 지표로 따로 확인.

## 방식

시작 모델: Z-Image Base + r64 v2 LoRA (지금까지 가장 좋음). 그 위에 새 LoRA를 학습한다.

### 1. 보상 (먼저 만들고, 먼저 검사)

| 층 | 무엇을 봄 | 어떻게 |
|---|---|---|
| 글리프 | 음절 하나하나의 획이 맞나 | 글자 상자를 음절 칸으로 잘라 qwen3vl에 "이 칸이 '깨'와 같은가, 예/아니오". 칸마다 폰트로 그린 정답 음절을 옆에 붙여 비교시킴 |
| 단어 | 목표 글자 전체 | 글자 상자만 잘라 dual OCR(PaddleOCR AND qwen3vl), `scripts/score_crops.py` |
| 전체 | 헛글자, 빠진 글자 | 전체 이미지 OCR에서 목표 밖 글자 수 |

보상 = 글리프 맞은 비율 x 0.6 + 단어 맞춤 x 0.3 - 헛글자 벌점 x 0.1 (초기값, 0단계에서 조정).

**0단계 보상 검사 (학습 전 통과해야 함).** 정답과 "자모 하나만 틀린" 오답을 자동으로 만든다.
- 같은 장면에 폰트로 정답(`도깨비`)과 오답(`도꺼비`, ㅐ->ㅓ / 쌍자음 -> 홑자음 / 받침 하나 바꿈)을 그리고 B안 harmonize를 거친다.
- 500쌍. 보상이 정답 쪽을 95% 이상 고르면 통과. 못 고르면 보상을 고친다(칸 자르기, 프롬프트, 확대 배율).
- 이 쌍은 학습에 쓰지 않는다.

### 2. 1단계: 오프라인 영역 DPO (싸다, 먼저)

- 프롬프트: 학습용 글자 목록에서 2,000개(seen 단어, unseen 단어, 복잡 음절 많은 단어 고르게). 평가 220개와 겹치지 않게.
- 프롬프트마다 이미지 4장(시드 4개). 보상을 매겨 가장 높은 것과 낮은 것을 한 쌍으로.
- 손실: Diffusion-DPO를 글자 상자 마스크 안에서만 계산(R-GDPO 방식). 마스크는 이미 있는 `glyph.layout()` 상자.
- B안 결과 중 dual OCR과 사람이 모두 통과한 것은 "정답 쪽" 예시로 섞는다(획 정답을 보여 줌).
- 새 LoRA rank 32, r64 v2는 고정.

### 3. 2단계: 온라인 GRPO (1단계가 효과 있을 때만)

- Flow-GRPO 방식. 프롬프트당 8장 그룹, 그룹 안 상대 보상으로 업데이트.
- 롤아웃 스텝은 16으로 줄인다. KL 벌점으로 Base에서 너무 멀어지지 않게.
- 1단계 LoRA에서 시작.

## 비용 (실측 속도로 계산)

| 항목 | 양 | 실측 속도 | GPU 시간 |
|---|---|---|---|
| 0단계 보상 검사 | 500쌍 harmonize + 채점 | harmonize 장당 약 10초, qwen3vl 채점 장당 약 3초 | 약 4 (L40S 1장) |
| 1단계 롤아웃 | 2,000 x 4 = 8,000장 | Base 28스텝 장당 약 30초 | 약 67 |
| 1단계 채점 | 8,000장 | 장당 약 5초 (칸 여러 개) | 약 11 |
| 1단계 DPO 학습 | 2,000쌍 x 몇 epoch | LoRA 학습 속도 초당 약 1장 | 몇 시간 |
| 2단계 GRPO | 미정 | 1단계 결과 보고 정함 | 1단계보다 큼 |

- 박스(L40S 1장)로 1단계는 며칠 걸린다. g7e.48xlarge(GPU 8장)면 롤아웃·채점을 8갈래로 나눠 돌린다.
- 롤아웃 속도는 g7e에서 첫 30분에 다시 잰다.

## 통과 기준 (평가 220개, 학습에 안 쓴 것)

| 지표 | 기준 | r64 v2 |
|---|---|---|
| unseen 단어 dual 맞춤 (상자만 채점) | 60% 이상 | 19% (전체 이미지 채점) |
| 사람 판정 20장, 획 맞음 | 15장 이상 | - |
| 일반 품질 | Base 대비 사람이 봐서 나빠지지 않음, 검증 loss 0.42 이하 | 0.408 |
| 보상 해킹 | 보상에 안 쓴 지표(PaddleOCR 단독, 사람 판정)가 보상과 같이 오름 | - |

## 위험

- **보상이 획을 못 봄.** 0단계에서 걸러 낸다. 통과 못 하면 학습하지 않는다.
- **보상 해킹.** 글자를 크고 단순하게만 그리는 쪽으로 갈 수 있다. 사람 판정과 PaddleOCR 단독 점수로 따로 본다.
- **unseen 음절.** OCR이 아예 못 읽는 음절(뇱, 꾔, 툟)은 단어 보상이 0이다. 글리프 층(정답 음절 옆에 두고 비교)이 이걸 메운다.

## 순서

1. `scripts/reward.py` (세 층 보상) + `scripts/make_jamo_pairs.py` (0단계 쌍) 작성.
2. 0단계 보상 검사. 95% 넘으면 다음.
3. `scripts/rollout.py` (프롬프트 x 시드 생성 + 보상 기록) 와 `scripts/train_dpo.py` (영역 마스크 DPO, `train_lora.py`의 데이터·체크포인트 코드 재사용).
4. 1단계 200프롬프트 스모크 -> 2,000프롬프트 본실행 -> 220개 평가.
5. 효과 있으면 2단계 GRPO 계획을 따로 쓴다.
